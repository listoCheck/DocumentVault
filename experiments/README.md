# Проверка измерения качества поиска

Из корня проекта выполните `gradlew.bat :experiments:run`. Программа сравнивает точное пословное совпадение с текущим поиском, устойчивым к части ошибок OCR, и выводит TP, FP, FN, TN, precision, recall и F1.

Набор `data/search-synthetic.tsv` содержит всего 12 вручную созданных примеров. Он предназначен для проверки вычислений и демонстрации ложноположительных результатов, а не для научного вывода о качестве системы. Например, нечёткое совпадение может принять разные фамилии за одну.

Для дипломного эксперимента нужен значительно больший размеченный набор, разные типы документов и реалистичные ошибки OCR. Наборы подбора и оценки следует разделять, чтобы не оптимизировать метод под проверочные данные. Состав, разметку и условия эксперимента необходимо документировать; персональные документы без разрешения использовать нельзя.

## Оценка OCR

`gradlew.bat :experiments:ocrMetrics` рассчитывает CER и WER для демонстрационного набора `data/ocr-synthetic.tsv`. В каждой строке файла находятся эталонный текст и распознанный текст, разделённые табуляцией; строки, начинающиеся с `#`, являются комментариями. Результат распознавания может быть пустым. Табуляцию и переносы строк внутри одного текста формат TSV не поддерживает, поэтому сложные документы нужно заранее разбить на сопоставимые строки или подготовить другой формат загрузки.

Другой набор можно передать командой `gradlew.bat :experiments:ocrMetrics --args="C:/path/to/dataset.tsv"`. На каждом примере рассчитывается расстояние Левенштейна, затем ошибки и длины эталонов суммируются: CER = сумма символьных ошибок / сумма символов эталона, WER = сумма ошибок слов / сумма слов эталона. Символы считаются как кодовые точки Unicode после нормализации NFC; пробелы, регистр и пунктуация в CER сохраняются. Слова разделяются пробельными символами, регистр и пунктуация сохраняются. Вставки могут дать значение больше 1.

Демонстрационный файл содержит три искусственные пары, а не результаты Tesseract. Его показатели проверяют только работу программы. Для исследования нужны отдельные изображения, ручные эталонные транскрипции и фактический вывод OCR, зафиксированные условия обработки и независимый набор оценки. Не включайте персональные документы в репозиторий.

Для запуска фактического OCR Windows-клиента подготовьте UTF-8 файл, где каждая строка содержит путь к изображению или PDF, табуляцию и эталонный текст. Относительные пути отсчитываются от папки этого файла. Затем выполните `gradlew.bat :experiments:ocrImages --args="C:/path/to/manifest.tsv"`. Используются те же `LocalOcr` и языковые модели `rus+eng`, что и в приложении. При необходимости путь к моделям задаётся переменной `VAULT_TESSDATA`. Пустые строки и строки-комментарии, начинающиеся с `#`, игнорируются; для каждого входного файла установлен предел 15 МиБ.

Команда выводит общие CER/WER и время обработки, включая чтение файла и инициализацию OCR. Конечные символы перевода строки в выводе OCR удаляются; остальные символы, регистр и пунктуация сохраняются. Для корректного сравнения эталон должен описывать то же содержимое и порядок строк, что ожидаются от OCR. Текущий формат эталона рассчитан на однострочные примеры; для многостраничных документов необходимо расширить формат, прежде чем оценивать их качество. Время включает первый запуск и зависит от устройства; для сравнения производительности нужны повторные измерения.

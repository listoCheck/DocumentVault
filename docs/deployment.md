# Подготовка сетевого сервера

В проект добавлен шаблон Docker Compose: Caddy принимает HTTPS, сервер доступен только во внутренней сети Compose, база хранится в отдельном томе. Серверный образ собран и локально проверен: процесс работает от отдельного пользователя, создаёт базу и отвечает на `/health`. Это черновик развёртывания: Compose с реальным доменом и выпуск сертификата ещё не проверены; нужны внешнее ограничение запросов, резервное копирование, мониторинг и проверка безопасности. Не используйте его для реальных персональных документов до проверки.

Для проверки на собственном сервере потребуются Docker с Compose, публичный домен, DNS-запись на сервер и доступные порты 80 и 443. Caddy получает сертификат автоматически при выполнении этих условий. Не используйте чужой домен.

```powershell
$env:VAULT_DOMAIN = 'vault.example.com'
docker compose config
docker compose up --build -d
```

Вместо примера укажите принадлежащий вам домен. Рабочая база лежит в томе `vault-data`; удаление тома приведёт к потере данных. Сертификаты хранятся в `caddy-data`. Автоматическое резервное копирование пока отсутствует.

Для локального сервера предусмотрено согласованное создание копии SQLite через `VACUUM INTO`. Укажите источник через `VAULT_DATABASE` и новый, ещё не существующий путь назначения:

```powershell
$env:VAULT_DATABASE = 'C:\path\documentvault.db'
.\gradlew.bat :server:backup --args='C:\path\documentvault-backup.db'
```

Для копии контейнера нужен доступ к тому же тому и установленный SQLite с командой `VACUUM INTO`, либо отдельная процедура, которая ещё не автоматизирована. Храните резервную копию отдельно и проверяйте восстановление. В копии зашифрованы документы и их закрытые метаданные, но идентификаторы, логины и хеши паролей защищены не шифрованием. Копия может содержать ещё действующие сессии на момент создания.

На клиенте задайте `VAULT_SERVER_URL` без завершающего слеша, например `https://vault.example.com`. Удалённый HTTP запрещён; локальный HTTP разрешён только для loopback. Сервер также требует отдельной защиты от перебора на уровне прокси: встроенный ограничитель хранится в памяти процесса, считает адрес внутреннего подключения к серверу и не рассчитан на несколько экземпляров и масштабную атаку. Из-за прокси он может ограничить всех клиентов одновременно.

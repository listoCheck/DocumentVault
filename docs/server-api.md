# Протокол локального прототипа

Адрес по умолчанию: `http://127.0.0.1:7070`. Встроенный сервер использует HTTP и по умолчанию доступен только локально. Для доступа через сеть необходим TLS на обратном прокси, а также защита от перебора и другие меры эксплуатации.

## Учётная запись и ключ

Клиент генерирует случайный 32-байтовый мастер-ключ и 16-байтовую соль. Он получает ключ восстановления из отдельного пароля с PBKDF2-HMAC-SHA256, 600 000 итераций, и шифрует мастер-ключ через `VaultCrypto.encrypt` с контекстом `master-key` в UTF-8. Сервер не должен получать ни мастер-ключ, ни пароль восстановления.

`POST /v1/accounts` принимает JSON-поля `username`, `password`, `recoverySalt`, `wrappedKey`. Последние два поля — стандартный Base64. Логин: 3–40 символов ASCII из букв, цифр и `_.-`; регистр не учитывается. Пароль входа: минимум 12 символов и не более 72 байт UTF-8. Успех: 201 и JSON с `id`. Имя, пароль входа и идентификатор видны серверу; хранится только хеш пароля.

`POST /v1/sessions` принимает JSON с `username` и `password`. При успехе возвращает `token` и время `expiresAt` в секундах Unix. Для последующих запросов передавайте заголовок `Authorization: Bearer <token>`. Срок токена — 24 часа. Сервер хранит его SHA-256, а не сам токен.

Для одного IP-адреса прототип принимает до 5 запросов входа за 10 минут и до 10 запросов регистрации за час; учитываются и успешные запросы. Следующие запросы получают 429. При успешном входе сервер удаляет из БД сессии с истёкшим сроком. Ограничители находятся только в памяти процесса, сбрасываются после его перезапуска и не рассчитаны на распределённую атаку. За обратным прокси сервер видит адрес прокси, поэтому все клиенты могут разделять один лимит. Для публичного развёртывания нужна независимая защита на границе сети.

Для прокси на том же хосте можно включить `VAULT_TRUST_LOOPBACK_PROXY=true`, при этом сервер обязан слушать только `127.0.0.1` или `::1`. Прокси должен перезаписывать `X-Real-IP` реальным адресом клиента. В этом режиме заголовок учитывается только от loopback-соединений; локальным процессам на сервере всё равно требуется доверять.

`GET /v1/vault` возвращает `recoverySalt` и `wrappedKey` для восстановления ключа на клиенте. `DELETE /v1/sessions/current` завершает текущую сессию.

## Документы

Клиент создаёт UUID документа, шифрует его содержимое и конфиденциальные метаданные на устройстве с помощью `VaultCrypto.encrypt`. Контекст для шифрования должен быть строкой `document:<UUID>` в UTF-8. Сервер проверяет формат оболочки лишь поверхностно и не может доказать, что клиент отправил зашифрованные данные.

- `POST /v1/documents`: заголовок `X-Document-Id` содержит UUID, тело — двоичная зашифрованная оболочка. Максимальный размер тела — 16 МиБ. Успех: 201.
- `GET /v1/documents`: список UUID и времени загрузки текущего пользователя, без содержимого и названий.
- `GET /v1/documents/{id}`: зашифрованная оболочка документа пользователя.
- `DELETE /v1/documents/{id}`: удаление документа пользователя.
- `GET /v1/documents/{id}/metadata` и `PUT /v1/documents/{id}/metadata`: чтение и сохранение зашифрованного текста OCR и подтверждённого срока. Формат оболочки такой же; контекст — `metadata:<UUID>`. Ограничение — 1 МиБ. Если метаданных нет, GET возвращает 404.

На каждую учётную запись действует ограничение: 1000 документов и 256 МиБ суммарного размера зашифрованных документов и метаданных. При превышении сервер возвращает 413 и отменяет запись. Удаление документа или уменьшение метаданных освобождает место. Квоты проверяются в транзакции SQLite и не ограничивают общее число аккаунтов или физический размер файла БД; для публичного сервера нужны дополнительные ограничения регистрации, диска и сетевого трафика.

Оболочка версии 1 состоит из байта версии `01`, 12-байтового случайного nonce и результата AES-256-GCM с 16-байтовым тегом. Дополнительные аутентифицируемые данные — указанный выше контекст. Сейчас вся оболочка загружается в память; потоковая обработка больших файлов не реализована.

Серверу видны логин, UUID и размеры объектов, время загрузки и сведения о сетевом соединении. Реализация пока не предусматривает смену пароля восстановления, удаление аккаунта, отзыв всех сессий и миграции схемы БД.
